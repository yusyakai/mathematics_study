# 問題データを作る・見直す手順

1. `docs/thinking-app/data-spec.md` の2〜5章（入力項目・分類の基準・選択肢・書き方のルール）を読む。
2. 問題文を原文どおりに確定し、基本情報を決める。`id` はファイル名と同じにし、`subject`・`unit`・`difficulty` は `catalog.js` の選択肢から選ぶ。
3. 注目箇所を洗い出す。問い → 状況 → 条件 の順に、解法の判断につながる部分を問題文から完全一致で引用する。引用どうしは重ねない。
4. 注目箇所ごとに気づきを書く。
   - 問題文に書いてあることから考えることだけを書く（方針・解答のまとめ・計算の流れは書かない）。
   - 1つの気づきには1つの考え。種類は data-spec.md 3.2 の判断順で決める。
   - `cue` は注目箇所の引用の一部にする。`thought` は1文・60字以内を目安にする。
5. 優先順位を振る。注目箇所は見る順番、気づきは 読み取り → 型の判定 → 解法の選択 → 注意 を目安にする。
6. 管理情報を書く。Claude が作った場合は `"source": "ai"`、`"model"` に使用モデル、`"reviewed": false`（人が確認するまで true にしない）。
7. ファイルを保存し、Hook が出す検証結果のエラーをなくす。警告は内容を見直し、残す場合は理由をユーザーに伝える。
8. `npm test` を実行し、必要に応じて `npm run dev` で http://localhost:5173/thinking/ を開いて表示を確かめる。
9. ユーザーには、作った注目箇所と気づきの一覧と、人が確認すべき点（分類に迷った箇所など）を伝える。
