# 着眼点トレーナー データ仕様書（入力項目と分類）

問題データを手作業でも AI でも同じ品質で作るための、入力項目の定義と分類の基準です。
アプリが読み込むデータ形式は **バージョン 4**（`schemaVersion: 4`）です。

- 形式の基準（必須項目・チェック内容）: [`src/thinking-app/lib/schema.js`](../../src/thinking-app/lib/schema.js)
- 選択肢の基準（科目・単元・難易度・役割・種類）: [`src/thinking-app/lib/catalog.js`](../../src/thinking-app/lib/catalog.js)

この文書とコードの内容が食い違うときは、コードが正しいものとして扱い、この文書を直してください。

---

## 1. データの全体像

1問 = 1ファイル（`src/thinking-app/data/<id>.json`）。中身は4つの区分に分かれます。

```
問題データ
├─ A. 問題の基本情報 … 題名・科目・単元・難易度・問題文・出典
├─ B. 注目箇所（focuses） … 問題文の「どこを見るか」。見る順番に優先順位を付ける
│    └─ C. 気づき（insights） … その箇所に「何が書いてあるから、何を考えるか」。1個ずつ表示する
└─ D. 管理情報（meta） … 誰が（手作業／AI）作ったか、人が確認したか
```

画面では、B の番号（＝優先順位）の順に注目箇所を示し、選ばれた注目箇所の C を優先順位の高いものから1個ずつ出します。

---

## 2. 入力項目一覧

「入力者」は、その項目を誰が決めるかを表します。

- 人：手作業で入力する人（先生）が決める
- AI：AI に作らせる場合は AI が下書きし、人が確認する
- 自動：入力しない（アプリや作成ツールが決める）

### A. 問題の基本情報

| 項目 | キー | 必須 | 入力者 | 形式・選択肢 | 説明・例 |
|---|---|---|---|---|---|
| 形式の版 | `schemaVersion` | ○ | 自動 | `4` | 作成ツールが付ける |
| ID | `id` | ○ | 人 | 半角英小文字・数字・`_` | ファイル名と同じ。例: `probability_002` |
| 題名 | `title` | ○ | 人・AI | 文字列 | 一覧に出す短い名前。例: `確率 基本` |
| 科目 | `subject` | ○ | 人・AI | 選択肢（4章） | 例: `数学A` |
| 単元 | `unit` | ○ | 人・AI | 科目ごとの選択肢（4章） | 例: `確率` |
| 難易度 | `difficulty` | ○ | 人 | `C` 基本 / `B` 応用 / `A` 入試対策 / `S` 実践 | |
| 問題文 | `problem` | ○ | 人 | 文字列 | 原文どおりに入力する。引用の基準になる |
| 出典 | `origin` | – | 人 | 文字列 | 例: `自作`、`教科書p.52 例題3` |

### B. 注目箇所（`focuses` の各要素）

| 項目 | キー | 必須 | 入力者 | 形式・選択肢 | 説明・例 |
|---|---|---|---|---|---|
| ID | `id` | ○ | 自動 | 半角英数字・`_`・`-` | 作成ツールが `f1`, `f2`… を付ける |
| 引用 | `quote` | ○ | 人・AI | 問題文の一部と完全一致 | 例: `2個取り出す` |
| 出現番号 | `occurrence` | – | 自動 | 1以上の整数 | 同じ引用が問題文に複数あるときの何番目か。省略時は1 |
| 役割 | `role` | ○ | 人・AI | `question` 問い / `condition` 条件 / `situation` 状況 | 3章で分類 |
| 優先順位 | `priority` | ○ | 人・AI | 1以上の整数（重複不可） | 見る順番。表示する番号になる |
| 気づき | `insights` | ○ | 人・AI | 配列（1個以上） | C を参照 |

### C. 気づき（`insights` の各要素）

| 項目 | キー | 必須 | 入力者 | 形式・選択肢 | 説明・例 |
|---|---|---|---|---|---|
| 優先順位 | `priority` | ○ | 人・AI | 1以上の整数（注目箇所の中で重複不可） | 1から順に1個ずつ表示する |
| 種類 | `kind` | ○ | 人・AI | `interpret` 読み取り / `identify` 型の判定 / `select` 解法の選択 / `caution` 注意 | 3章で分類 |
| 手がかりの語句 | `cue` | ○ | 人・AI | 注目箇所の引用の一部と完全一致 | 「〇〇と書いてある」の〇〇。例: `取り出す` |
| 考えること | `thought` | ○ | 人・AI | 1文、60字以内が目安 | 例: `順番を考えないので、nPr ではなく nCr で数える` |

### D. 管理情報（`meta`）

| 項目 | キー | 必須 | 入力者 | 形式・選択肢 | 説明 |
|---|---|---|---|---|---|
| 作成方法 | `source` | ○ | 人 | `manual` 手作業 / `ai` AI生成 | |
| 使用モデル | `model` | AI のとき | 人 | 文字列 | AI で作ったときに使ったモデル名 |
| 確認済み | `reviewed` | ○ | 人 | `true` / `false` | 人が内容を確かめたら `true`。`false` の間は一覧に「未確認」と出る |

### 入力しない項目（アプリが自動で決める）

| 内容 | 決め方 |
|---|---|
| 問題文の中での位置 | 引用（`quote`・`cue`）から自動で求める。文字位置は書かない |
| 表示する番号・並び順 | `priority` の小さい順 |
| 注目箇所の色 | 番号の順に自動で割り当てる |
| 学習の完了記録・設定 | 学習する人の端末に保存する（データには含めない） |

## 3. 分類の基準

### 3.1 注目箇所の役割（`role`）：その部分に「何が書かれているか」

| 役割 | キー | 定義 | 例 |
|---|---|---|---|
| 問い | `question` | 何を求めるか・何を示すかが書かれている部分 | `確率を求めよ`、`最大値と最小値を求めよ`、`2個とも赤玉`（求める事象） |
| 条件 | `condition` | 数・式・範囲・制約など、解くときに使う条件が書かれている部分 | `x + y = 3, xy = 2`、`(0 ≤ x ≤ 3)`、`赤玉3個、白玉5個` |
| 状況 | `situation` | 操作・試行・図形の配置など、問題の場面が書かれている部分 | `2個取り出す`、`さいころを2回投げる`、`円に内接する四角形` |

迷ったときは次の順に確かめます。

1. 答えるべき対象（求めるもの・示すこと）を含む → **問い**
2. 数・式・範囲そのものが書かれている → **条件**
3. 動作・操作・場面の設定が書かれている → **状況**

1つの引用に複数の役割が混ざるときは、引用を分けて別の注目箇所にします。

### 3.2 気づきの種類（`kind`）：そこから「どんな考え方をするか」

| 種類 | キー | 定義 | 文末の目安 | 例 |
|---|---|---|---|---|
| 読み取り | `interpret` | 書いてあることの意味・数量・性質を言い換える。新しい判断は含まない | 〜だ／〜とわかる | `玉は全部で 3 + 5 = 8 個` |
| 型の判定 | `identify` | 問題がどの型・どの分野の考え方を使う場面かを見抜く | 〜の問題 | `対称式の値を求める問題` |
| 解法の選択 | `select` | 使う公式・手法・手順を決める | 〜を使う／〜する／〜で求める | `nPr ではなく nCr で数える` |
| 注意 | `caution` | 間違えやすい点・確認が必要な点・場合分けの必要に気づく | 〜に注意／〜を確認する | `軸 x = 1 が範囲の中にあるかを必ず確認する` |

迷ったときは、**上から順に**当てはまるかを確かめ、最初に当てはまったものにします（作成ツールの「役割と種類の選び方」にも同じ表を出しています）。

1. 間違いを防ぐための確認・場合分けを促しているか → **注意**
2. 使う公式・手法・手順を決めているか → **解法の選択**
3. 問題の型や分野を名指ししているか → **型の判定**
4. 上のどれでもなく、書いてあることを言い換えているか → **読み取り**

よくある迷い：

| 気づきの例 | 種類 | 理由 |
|---|---|---|
| 頂点が範囲内かを確認する | 注意 | 「確認する」はミスを防ぐ確認（判断順1） |
| 平方完成して頂点を求める | 解法の選択 | 手順を決めている |
| 下に凸の放物線 | 読み取り | 係数の符号から形を言い換えている |
| 定義域が限られた最大・最小の問題 | 型の判定 | 型を名指ししている |
| 取り出すだけで並べない → 順番は関係ない | 読み取り | 判断（nCr を使う）は別の気づきに分ける |

### 3.3 対象外のもの（いまは扱わない）

- **「書いていないこと」からの気づき**（例：「並べる」とは書いていない）。必要になったら項目を追加して扱いを決めます。
- **方針や解答のまとめ**、答えまでの計算の流れ。このアプリは「問題文から何を考えるか」を示すもので、解答例ではありません。

## 5. 書き方のルール

1. **1つの気づきには1つの考えだけ**を書く。読み取り → 解法の選択のように**種類の違う考えが続くとき**は、気づきを分けて優先順位で並べる（「x² の係数が正 → 下に凸」のような同じ考えの言い換えは1つでよい）。
2. **書いてあることから考える**。`cue` には問題文に実際にある語句を、注目箇所の引用の中から選ぶ。
3. **短く**。`thought` は1文で、60字以内を目安にする。
4. **引用は完全一致**。全角・半角、空白、記号（`−` と `-`、`²` など）も問題文と同じにする。
5. **注目箇所は重ねない**。同じ文字列が問題文に複数あるときだけ `occurrence` を使う。
6. **優先順位の目安**
   - 注目箇所：問い → 状況 → 条件 の順に見ると、何のために条件を使うかがわかりやすい。問題に合わせて変えてよい。
   - 気づき：読み取り → 型の判定 → 解法の選択 → 注意 の順にすると、「読む → わかる → 決める → 確かめる」の流れになる。
7. 1つの注目箇所の気づきは5個まで、1問の注目箇所は8個までを目安にする（超えると警告）。

## 6. チェック内容

作成ツールと `npm run validate:thinking` は、次の内容を自動でチェックします。

| 区分 | 内容 | 扱い |
|---|---|---|
| エラー | 必須項目がない／選択肢にない値／ID の文字種／ファイル名と ID の不一致 | 一覧に表示されない |
| エラー | 引用が問題文にない／注目箇所が重なる／`cue` が引用の一部でない | 一覧に表示されない |
| エラー | 優先順位が整数でない・重複している | 一覧に表示されない |
| 警告 | 気づきが60字を超える／気づき・注目箇所が多すぎる | 表示されるが見直し推奨 |
| 警告 | 「問い」の注目箇所がない／「解法の選択」の気づきがない | 表示されるが見直し推奨 |
| 警告 | 優先順位が1から連続していない／同じ内容の気づきがある／AI生成なのにモデル名がない | 表示されるが見直し推奨 |

## 7. 作成と公開の手順

### 作成ツールで作る（おすすめ）

1. アプリの一覧の下にある「問題データを作る（作成ツール）」を開く
2. 「白紙から作る」または「既存の問題をもとに作る」を選ぶ
3. 基本情報を入力し、問題文の中をドラッグ（スマホは長押し）して注目箇所を追加する
4. 各注目箇所に気づきを入力する（種類は「役割と種類の選び方」を参考にする）
5. 「チェック結果」のエラーをなくし、「画面で確認」で表示を確かめる
6. 内容を確認したら「内容を確認した」にチェックを入れ、JSON を書き出す
   - PC の Chrome・Edge：「保存先フォルダを選んで保存」で、選んだフォルダに直接保存する（選んだフォルダは次回も使う。同じ名前のファイルがあるときは上書きを確認する）
   - そのほかのブラウザ：「ファイルに保存」でダウンロードフォルダに保存する
7. GitHub のリポジトリで `src/thinking-app/data` を開き、「Add file → Upload files」でファイルを追加する
8. main ブランチに入ると自動でチェック・公開される

下書きは作業した端末のブラウザにだけ保存されます。別の端末で続けるときは、JSON を書き出して「JSON を読み込んで作る」で読み込みます。

### JSON を直接書く場合

`src/thinking-app/data/probability_001.json` を参考に書き、`npm run validate:thinking` でチェックします。

## 8. AI に下書きを作らせる場合

アプリには AI を組み込んでいません。手元の AI チャット（Claude など）で下書きを作り、作成ツールで確認します。

1. 作成ツールの「AI に下書きを作ってもらう」に問題文を入れ、「**AI用の指示文をコピー**」を押す
2. AI チャットに貼り付けて送る
3. AI が出力した JSON を、作成ツールの「JSON を読み込んで作る」に貼り付ける（「```json」の囲みや前後の説明文は自動で取り除く）
4. 管理情報は「AI生成」「未確認」が自動で入る。使ったモデル名を入れ（入れるまで警告が出る）、チェック結果のエラーを直す
5. 内容を人が確認してから「内容を確認した」にチェックし、保存する

指示文は `src/thinking-app/lib/aiPrompt.js` が、科目・単元・役割・種類の定義（`catalog.js`）から組み立てる。分類の基準を変えると指示文にも自動で反映される。

アプリに AI を組み込むときは、`schema.js` の `THINKING_JSON_SCHEMA` を AI の構造化出力の形式指定にそのまま使えます。

## 9. 記入例

`src/thinking-app/data/probability_001.json` の一部です。

```json
{
  "id": "f2",
  "quote": "2個取り出す",
  "role": "situation",
  "priority": 2,
  "insights": [
    { "priority": 1, "kind": "interpret", "cue": "取り出す", "thought": "取り出すだけで並べない → 選んだ順番は関係ない" },
    { "priority": 2, "kind": "select", "cue": "取り出す", "thought": "順番を考えないので、nPr ではなく nCr で数える" }
  ]
}
```

- 「取り出す」と書いてある → まず意味を読み取り（並べない）、次に解法を選ぶ（nCr）、という2つの考えを、2つの気づきに分けている
- 判断の流れどおりに、読み取り（1）→ 解法の選択（2）の優先順位にしている
