# 着眼点トレーナー 仕様書

問題文の「どこを見て」「そこに何が書いてあるから」「何を考える・判断するか」を、注目箇所ごとに1つずつ表示する学習アプリです。
入力項目と分類の詳細は [データ仕様書](data-spec.md) にまとめています。

---

## 1. 目的と方針

- **目的**：解き方の暗記ではなく、問題文から解法を選ぶまでの思考の過程（着眼点）を身につける。
- **表示するもの**：問題文の注目箇所と、そこに書いてあることから考えること（気づき）。
- **表示しないもの**：方針や解答のまとめ、答えまでの計算の流れ。
- **見せ方**：いきなり全部は出さない。見る順番に番号を付け、学習者が操作するたびに優先順位の高い気づきから1個ずつ出す。
- **費用**：アプリストアやサーバーを使わず、無料の静的ホスティング（GitHub Pages）で公開する。
- **将来**：VR グラス（Quest、Android XR など）でも同じデータと考え方で表示できるようにする。

## 2. 利用者と利用場面

| 利用者 | 場面 | 使う画面 |
|---|---|---|
| 生徒 | スマホで問題文を見ながら、着眼点を1つずつ確かめる | 一覧、画面で見る、ARで見る、振り返り |
| 先生 | 問題カードを印刷・画面表示して授業や自習で使う | カード |
| 先生 | 問題データを作る・直す・確認する | 作成ツール |

## 3. 画面と機能

| 画面 | 主な機能 |
|---|---|
| 一覧 | 問題の一覧、科目での絞り込み、完了した問題の表示、作成ツールへの入口 |
| 画面で見る | 問題文に注目箇所の番号を表示し、タップで気づきを1個ずつ表示。手がかりの語句を強調 |
| ARで見る | スマホのカメラで問題カードを認識し、注目箇所の番号と気づきの吹き出しを重ねる。カード上の注目箇所をタップして選べる |
| カード | AR の目印になる問題カードの表示・画像保存・印刷 |
| 振り返り | すべての注目箇所と気づきを順番どおりに一覧表示。気づきの種類ごとの数 |
| 作成ツール | 下書きの一覧、白紙・既存の問題・JSON からの作成 |
| 問題データの編集 | 範囲選択で注目箇所を追加、気づきの入力と並べ替え、その場でのチェック、プレビュー、JSON の書き出し |

### 3.1 学習の流れ

1. 問題文だけを表示し、「どこから見ればいい？」と促す
2. 「見る順番を表示」で注目箇所に番号を付ける（次に見る番号を点滅で示す）
3. 注目箇所をタップすると、優先順位1の気づきが出る。同じ箇所をもう一度タップするか「次の気づき」で次の1個が出る
4. その箇所の気づきを見終えたら「次の注目箇所へ」で、まだ開いていない中で優先順位が最も高い箇所へ進む
5. すべて見終えたら「振り返りを見る」で全体を確認する。完了は端末に記録され、一覧に表示される

**考えてから見る**（設定）をオンにすると、手順3で答えの前に問いかけ（例：「『取り出す』から何が読み取れる？」）を出し、もう一度の操作で答えを出す。問いかけの文は気づきの種類から自動で作る。

### 3.2 気づきの表示内容

- 種類のラベル（読み取り／型の判定／解法の選択／注意）
- 「〇〇と書いてある」（手がかりの語句。問題文の中でも強調する）
- → 考えること

## 4. データ

- 1問 = 1ファイル（`src/thinking-app/data/<id>.json`）。置くだけで一覧に載る。
- 読み込み時に `validateThinking()` で検証し、エラーのあるデータは一覧に出さない（一覧の下に理由を表示）。
- 学習の記録・設定・下書きは端末の localStorage にだけ保存し、外部には送らない。

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| 対応環境 | iPhone の Safari、Android の Chrome の最新版。PC のブラウザ |
| 通信 | HTTPS 必須（カメラのため）。AR の部品（three.js・MindAR）と Web フォントは CDN から読み込むため、通信が必要 |
| 性能 | AR は初回だけカードの解析に数秒〜十数秒かかる。2回目以降は端末に保存した解析結果を使う |
| アクセシビリティ | ボタンはキーボードで操作でき、フォーカスが見える。新しく出た気づきは読み上げ対象（aria-live）。白文字が読める濃さの色を使う。「動きを減らす」設定ではアニメーションを止める |
| 個人情報 | 扱わない。データにも生徒の情報を入れない |
| 費用 | 無料（GitHub Pages で公開） |

## 6. 品質の確認

| 確認 | コマンド | 実行のタイミング |
|---|---|---|
| データのチェック | `npm run validate:thinking` | 作業ブランチへの push（CI）、main への push（公開前）、Claude がデータを編集したとき（Hook） |
| Lint | `npm run lint:thinking` | CI |
| 単体テスト | `npm test` | CI、公開前 |
| ビルド | `npm run build` | CI、公開前 |
| まとめて実行 | `npm run check:thinking` | 手元での確認 |

単体テストの対象：データ形式のチェック、優先順位の並べ替えと位置の計算、学習の進み具合、作成ツールの読み込み・書き出し、タップ位置の判定、データ仕様書と選択肢の一致。

## 7. 既知の制約

- **数式の表記**：問題文は文字で書く（`x²`、`₃C₂` など）。分数・根号・積分記号などを含む問題は表しにくい。
- **AR の目印**：AR はこのアプリのカードでのみ動く。教科書やプリントをそのまま映しても認識しない。
- **下書きの共有**：下書きは作業した端末にだけ保存される。別の端末へは JSON の書き出し・読み込みで移す。
- **作成ツールの公開範囲**：作成ツールは誰でも開ける（データを公開する権限は GitHub 側で管理される）。

## 8. 改善の検討結果

### 8.1 今回実施したこと

| 区分 | 内容 | 理由 |
|---|---|---|
| 入力項目 | 注目箇所の役割（問い／条件／状況）と、気づきの種類（読み取り／型の判定／解法の選択／注意）を必須にした | 手作業でも AI でも同じ基準で分類でき、表示や振り返りに使えるようにするため |
| 入力項目 | 手がかりの語句を注目箇所の引用の一部に限定し、問題文の中で強調できるようにした | 「何が書いてあるから」を正確に示すため |
| 入力項目 | 科目・単元・難易度を選択肢にした | 表記ゆれを防ぎ、絞り込みに使うため |
| 入力項目 | チェックを「エラー」と「警告（内容の見直し推奨）」に分けた | 使えないデータと、質の確認が必要なデータを区別するため |
| 学習 | 考えてから見る（問いかけ → 答え）を追加した | 答えを見る前に自分で考える時間を作るため |
| 学習 | 手がかりの語句の強調、種類・役割のラベル、振り返り、完了の記録を追加した | 何を手がかりにどう考えたかを意識させるため |
| 作成 | 作成ツール（範囲選択・その場のチェック・プレビュー・書き出し・読み込み・下書き）を追加した | JSON を手で書かずに、分類の基準に沿って入力できるようにするため |
| 操作性 | スマホの「戻る」操作で1つ前の画面に戻れるようにした | 誤ってアプリを閉じないようにするため |
| AR | カメラが使えないときの案内と「画面で見る」への切り替え、準備中に画面を離れたときの中断、タップ判定の改善 | 失敗時に行き止まりにならないようにするため |
| 品質 | 単体テスト、CI、公開前のテスト、データ仕様書を整備した | 変更で壊れていないことを毎回確かめるため |

### 8.2 今後の候補

優先度は、学習効果と作る手間から判断した目安です。

| 優先度 | 候補 | 内容 | メモ |
|---|---|---|---|
| 高 | 予想モード | 番号を出す前に、学習者が「ここが大事」と思う箇所をタップし、正解の注目箇所と比べる | 「どこを見るか」を自分で考える練習になる |
| 高 | 自己評価と復習 | 気づきごとに「自分で気づけた／気づけなかった」を記録し、気づけなかったものを後で出す | 端末内の保存で実現できる |
| 高 | 数式の表記 | 問題文に分数・根号などの数式を書けるようにする（KaTeX など） | 引用の照合方法とカードの描画の見直しが必要 |
| 中 | 「書いていないこと」の気づき | 「〇〇とは書いていない」から考える気づきを、種類の軸とは別の項目として扱う | 必要な場面と書き方の基準を決めてから |
| 中 | 作成ツールの分離 | 作成ツールを生徒用の一覧から外す（別のURL・簡単な合言葉など） | 生徒が迷わないようにする |
| 中 | AR の認識データの事前作成 | 公開時にカードの解析結果を作っておき、初回の待ち時間をなくす | ビルド時にブラウザを使う処理が必要 |
| 中 | オフライン対応（PWA） | ホーム画面に追加して、通信が弱い場所でも画面で見るを使えるようにする | AR の部品も端末に保存する必要がある |
| 将来 | AI による下書き生成 | 問題文から AI が注目箇所と気づきを下書きし、人が確認して公開する | API キーを隠すためのサーバーが必要。`THINKING_JSON_SCHEMA` を構造化出力に使う |
| 将来 | プリントの撮影から作成 | 撮影した問題文を読み取り、下書きを作る | 文字・数式の読み取りと位置合わせが課題 |
| 将来 | VR グラス対応 | Quest・Android XR のブラウザ（WebXR）で同じデータを空間に表示する | 表示部分の追加で対応できる構成にしている |
