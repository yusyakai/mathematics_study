# 着眼点トレーナー 仕様書

問題文の「どこを見て」「そこに何が書いてあるから」「何を考える・判断するか」を、注目箇所ごとに1つずつ表示する学習アプリです。
入力項目と分類の詳細は [データ仕様書](data-spec.md) にまとめています。

---

## 1. 目的と方針

- **目的**：解き方の暗記ではなく、問題文から解法を選ぶまでの思考の過程（着眼点）を身につける。
- **表示するもの**：問題文の注目箇所と、そこに書いてあることから考えること（気づき）。
- **表示しないもの**：方針や解答のまとめ、答えまでの計算の流れ。
- **見せ方**：いきなり全部は出さない。見る順番に番号を付け、学習者が操作するたびに優先順位の高い気づきから1個ずつ出す。
- **費用**：アプリストアやサーバーを使わず、無料の静的ホスティング（GitHub Pages）で公開する。
- **進め方**：まず PC・スマホの画面で使える形（カメラなしの立体表示）で作り、その後スマートグラス・VR グラス（Quest、Android XR など）に広げる。画面・カメラ・グラスで同じデータとシーン部品を使う（9章）。

## 2. 利用者と利用場面

| 利用者 | 場面 | 使う画面 |
|---|---|---|
| 生徒 | PC・スマホの画面で問題文を見ながら、着眼点を1つずつ確かめる | 一覧、学習画面（立体・文字）、振り返り |
| 生徒 | 印刷したカードをスマホのカメラで映して確かめる | 学習画面（カメラ）、カード |
| 先生 | 授業で PC の画面（プロジェクター）に映して説明する | 学習画面（立体） |
| 先生 | 問題データを作る・直す・確認する | 作成ツール |

## 3. 画面と機能

| 画面 | 主な機能 |
|---|---|
| 一覧 | 問題の一覧、科目での絞り込み、完了した問題の表示、作成ツールへの入口。「画面で見る」は前回の表示（立体か文字）で、「ARで見る」はカメラ表示で学習画面を開く |
| 学習画面 | 上（PC・横向きでは左）に問題の表示、下（右）に注目箇所と気づきの一覧。表示は「立体」「文字」「カメラ」を切り替えられ、進み具合は引き継ぐ |
| └ 立体 | カメラなしで、問題カード・注目箇所の番号・吹き出し・線を画面の中の立体空間に置く。カード上の注目箇所をクリック／タップして選ぶ。ドラッグで傾き、拡大縮小・移動ができ、「視点を戻す」で元に戻る。横長の画面では吹き出しをカードの右、縦長では上に置く |
| └ 文字 | 問題文の注目箇所をボタンにして、手がかりの語句を強調する。立体表示が使えない環境や、文字を大きく読みたいとき |
| └ カメラ | スマホのカメラで問題カードを認識し、立体表示と同じ番号・吹き出し・線をカードの上に重ねる。スマホの縦持ちでは一覧を映像に重ねて表示する |
| カード | カメラ表示の目印になる問題カードの表示・画像保存・印刷 |
| 振り返り | すべての注目箇所と気づきを順番どおりに一覧表示。気づきの種類ごとの数 |
| 作成ツール | 下書きの一覧、白紙・既存の問題・JSON からの作成 |
| 問題データの編集 | 範囲選択で注目箇所を追加、気づきの入力と並べ替え、その場でのチェック、プレビュー、JSON の書き出し |

### 3.1 学習の流れ

1. 問題文だけを表示し、「どこから見ればいい？」と促す
2. 「見る順番を表示」で注目箇所に番号を付ける（次に見る番号を点滅で示す）
3. 注目箇所をタップ（PC はクリック）すると、優先順位1の気づきが出る。同じ箇所をもう一度選ぶか「次の気づき」で次の1個が出る
4. その箇所の気づきを見終えたら「次の注目箇所へ」で、まだ開いていない中で優先順位が最も高い箇所へ進む
5. すべて見終えたら「振り返りを見る」で全体を確認する。完了は端末に記録され、一覧に表示される

**考えてから見る**（設定）をオンにすると、手順3で答えの前に問いかけ（例：「『取り出す』から何が読み取れる？」）を出し、もう一度の操作で答えを出す。問いかけの文は気づきの種類から自動で作る。

### 3.2 気づきの表示内容

- 種類のラベル（読み取り／型の判定／解法の選択／注意）
- 「〇〇と書いてある」（手がかりの語句。問題文の中でも強調する）
- → 考えること

### 3.3 操作

| 操作 | PC | スマホ |
|---|---|---|
| 注目箇所を選ぶ・次の気づき | 注目箇所をクリック、番号ボタン、数字キー（1〜9） | 注目箇所をタップ、番号ボタン |
| 次へ（答え・次の気づき・次の注目箇所・振り返り） | 一覧の青いボタン、→ キー、N キー | 一覧の青いボタン |
| 立体表示を傾ける・拡大縮小・移動 | ドラッグ・ホイール・右ドラッグ | ドラッグ・ピンチ・2本指で移動 |
| 視点を戻す | 「視点を戻す」ボタン | 同左 |

立体表示の注目箇所には透明なボタンを重ねているので、キーボード（Tab キー）や読み上げでも選べる。
注目箇所と吹き出しをつなぐ線は、問題文の文字の上を横切らないよう、行間とカードの右の余白を通す。

## 4. データ

- 1問 = 1ファイル（`src/thinking-app/data/<id>.json`）。置くだけで一覧に載る。
- 読み込み時に `validateThinking()` で検証し、エラーのあるデータは一覧に出さない（一覧の下に理由を表示）。
- 学習の記録・設定・下書きは端末の localStorage にだけ保存し、外部には送らない。

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| 対応環境 | PC のブラウザ（Chrome・Edge・Safari・Firefox の最新版）、iPhone の Safari、Android の Chrome。立体・カメラ表示には WebGL が必要（使えない場合は文字表示に切り替える案内を出す） |
| 通信 | HTTPS 必須（カメラのため）。立体・カメラ表示の部品（three.js・MindAR）と Web フォントは CDN から読み込むため、通信が必要 |
| 性能 | 立体表示は操作したときだけ描き直す（止まっているときは電池を使わない）。カメラ表示は初回だけカードの解析に数秒〜十数秒かかり、2回目以降は端末に保存した解析結果を使う。表示を切り替えるたびに WebGL の資源を解放する |
| アクセシビリティ | ボタンはキーボードで操作でき、フォーカスが見える。新しく出た気づきは読み上げ対象（aria-live）。白文字が読める濃さの色を使う。「動きを減らす」設定ではアニメーションを止める |
| 個人情報 | 扱わない。データにも生徒の情報を入れない |
| 費用 | 無料（GitHub Pages で公開） |

|---|---|---|
| データのチェック | `npm run validate:thinking` | 作業ブランチへの push（CI）、main への push（公開前）、Claude がデータを編集したとき（Hook） |
| Lint | `npm run lint:thinking` | CI |

| まとめて実行 | `npm run check:thinking` | 手元での確認 |

単体テストの対象：データ形式のチェック、優先順位の並べ替えと位置の計算、学習の進み具合と次の操作、作成ツールの読み込み・書き出し、タップ位置の判定、立体表示の配置（吹き出しの位置・線の経路・カメラの距離）、キー操作、表示の選び方、データ仕様書と選択肢の一致。

## 7. 既知の制約

- **数式の表記**：問題文は文字で書く（`x²`、`₃C₂` など）。分数・根号・積分記号などを含む問題は表しにくい。
- **カメラ表示の目印**：カメラ表示はこのアプリのカードでのみ動く。教科書やプリントをそのまま映しても認識しない。
- **立体表示の文字**：吹き出しの文字は画像として描くため、読み上げには一覧（右・下）の同じ内容を使う。
- **下書きの共有**：下書きは作業した端末にだけ保存される。別の端末へは JSON の書き出し・読み込みで移す。
- **作成ツールの公開範囲**：作成ツールは誰でも開ける（データを公開する権限は GitHub 側で管理される）。

## 8. 改善の検討結果

### 8.1 今回実施したこと

| 区分 | 内容 | 理由 |
|---|---|---|
| 入力項目 | 注目箇所の役割（問い／条件／状況）と、気づきの種類（読み取り／型の判定／解法の選択／注意）を必須にした | 手作業でも AI でも同じ基準で分類でき、表示や振り返りに使えるようにするため |
| 入力項目 | 手がかりの語句を注目箇所の引用の一部に限定し、問題文の中で強調できるようにした | 「何が書いてあるから」を正確に示すため |
| 入力項目 | 科目・単元・難易度を選択肢にした | 表記ゆれを防ぎ、絞り込みに使うため |
| 入力項目 | チェックを「エラー」と「警告（内容の見直し推奨）」に分けた | 使えないデータと、質の確認が必要なデータを区別するため |
| 学習 | 考えてから見る（問いかけ → 答え）を追加した | 答えを見る前に自分で考える時間を作るため |
| 学習 | 手がかりの語句の強調、種類・役割のラベル、振り返り、完了の記録を追加した | 何を手がかりにどう考えたかを意識させるため |
| 作成 | 作成ツール（範囲選択・その場のチェック・プレビュー・書き出し・読み込み・下書き）を追加した | JSON を手で書かずに、分類の基準に沿って入力できるようにするため |
| 操作性 | スマホの「戻る」操作で1つ前の画面に戻れるようにした | 誤ってアプリを閉じないようにするため |
| AR | カメラが使えないときの案内と「画面で見る」への切り替え、準備中に画面を離れたときの中断、タップ判定の改善 | 失敗時に行き止まりにならないようにするため |
| 品質 | 単体テスト、CI、公開前のテスト、データ仕様書を整備した | 変更で壊れていないことを毎回確かめるため |
| 表示 | カメラなしの立体表示を追加し、「画面で見る」の標準にした。学習画面を1つにまとめ、立体・文字・カメラを進み具合を保ったまま切り替えられるようにした | カードをカメラで映さなくても、PC・スマホの画面だけで AR と同じ見せ方を使えるようにするため |
| 表示 | PC は横並び（左に表示・右に一覧）、スマホは上下に配置。横長の画面では吹き出しをカードの右に置く | 画面の形に合わせて大きく見せるため |
| 表示 | 線が問題文の文字を横切らない経路にした（行間と余白を通す。番号の丸の下を通る） | 線で文字が読みにくくならないようにするため |
| 操作 | PC のキー操作（数字キー・→ キー）、立体表示の傾き・拡大縮小・視点を戻す、注目箇所の透明ボタン | マウス・キーボードで手早く操作でき、読み上げでも選べるようにするため |
| 構成 | カード・吹き出し・線を表示先に依存しない「シーン部品」にし、画面とカメラを「表示先」として分けた | スマートグラスへの拡張を、表示先の追加だけで行えるようにするため（9章） |

### 8.2 今後の候補

優先度は、学習効果と作る手間から判断した目安です。

| 優先度 | 候補 | 内容 | メモ |
|---|---|---|---|
| 高 | 予想モード | 番号を出す前に、学習者が「ここが大事」と思う箇所をタップし、正解の注目箇所と比べる | 「どこを見るか」を自分で考える練習になる |
| 高 | 自己評価と復習 | 気づきごとに「自分で気づけた／気づけなかった」を記録し、気づけなかったものを後で出す | 端末内の保存で実現できる |
| 高 | 数式の表記 | 問題文に分数・根号などの数式を書けるようにする（KaTeX など） | 引用の照合方法とカードの描画の見直しが必要 |
| 中 | 「書いていないこと」の気づき | 「〇〇とは書いていない」から考える気づきを、種類の軸とは別の項目として扱う | 必要な場面と書き方の基準を決めてから |
| 中 | 作成ツールの分離 | 作成ツールを生徒用の一覧から外す（別のURL・簡単な合言葉など） | 生徒が迷わないようにする |
| 中 | AR の認識データの事前作成 | 公開時にカードの解析結果を作っておき、初回の待ち時間をなくす | ビルド時にブラウザを使う処理が必要 |
| 中 | オフライン対応（PWA） | ホーム画面に追加して、通信が弱い場所でも画面で見るを使えるようにする | AR の部品も端末に保存する必要がある |
| 将来 | AI による下書き生成 | 問題文から AI が注目箇所と気づきを下書きし、人が確認して公開する | API キーを隠すためのサーバーが必要。`THINKING_JSON_SCHEMA` を構造化出力に使う |
| 将来 | プリントの撮影から作成 | 撮影した問題文を読み取り、下書きを作る | 文字・数式の読み取りと位置合わせが課題 |
| 次 | スマートグラス・VR グラス対応 | Quest・Android XR のブラウザ（WebXR）で同じシーンを空間に表示する | 表示先（`xrHost`）を1つ追加する。手順は9章 |

## 9. 表示の構成とスマートグラスへの拡張

学習の状態・見た目（シーン）・表示先を分け、表示先を足すだけで新しい機器に対応できるようにしている。

```
学習の状態（lib/progress.js、useLearning）
   │ view: 番号を出したか・開いている注目箇所・出した気づきの数・強調する語句
   ▼
シーン部品（lib/scene/thinkingScene.js）
   │ 問題カード・注目箇所のハイライト・吹き出し・線をまとめた three.js の group
   │ 配置の計算は lib/scene/layout.js（純粋な関数・単体テストあり）
   ▼
表示先（lib/hosts/）… group をどこに置き、どう操作するかだけを受け持つ
   ├ screenHost.js … PC・スマホの画面。固定のカメラで見る。クリック／タップ・ドラッグ・キー操作
   ├ cameraHost.js … スマホのカメラ。MindAR が認識したカードの上に group を置く
   └ （次）xrHost.js … スマートグラス・VR グラス。WebXR で目の前の空間に group を置く
```

画面に出す2D の部品（注目箇所と気づきの一覧 `FocusGuide`、表示の切り替え `LearnView`）は、どの表示先でも共通に使う。

### スマートグラス対応（xrHost）の進め方

1. three.js の WebXR 機能（`renderer.xr`）で `immersive-ar`（パススルー）または `immersive-vr` のセッションを始める。
2. シーン部品の group を、目の前 50〜60cm・目の高さに置く。カード幅が 30cm 前後になるよう縮尺を合わせる。
3. コントローラーや手のレイを Raycaster に渡し、シーン部品の `pick()` で注目箇所を選ぶ（画面・カメラと同じ判定）。
4. 一覧（`FocusGuide`）は没入中は表示されないため、次の操作のボタンと気づきの一覧をシーンの中に置く（吹き出しと同じく canvas に描く）。
5. 学習画面の表示の切り替えに「グラス」を追加する（`lib/display.js`）。
