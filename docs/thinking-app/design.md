# 着眼点トレーナー デザインガイド

画面の見た目と操作感の方針をまとめます。画面を変えるときは、この方針に沿っているかを確かめてください。
実装は `src/thinking-app/app.css`（画面）と `src/thinking-app/lib/canvasRender.js`（問題カード・吹き出しの画像）にあります。

## 1. コンセプト

**「問題文に蛍光ペンで印をつけながら読む」**

- 主役は問題文と気づき。飾りは控えめにし、注目箇所の色と手がかりの語句の強調（蛍光ペンの黄色）が目に入るようにする。
- 落ち着いた藍色をアプリの色（ブランド色）にし、ボタン・進み具合・リンクに使う。
- 一度に1つのことだけを示す（次に押すボタンは常に1つ、気づきは1つずつ出す）。

## 2. 色

色は `app.css` 冒頭のトークン（CSS 変数）だけを使います。ダーク表示はトークンを差し替えるだけで切り替わります。

| トークン | 用途 |
|---|---|
| `--bg` / `--surface` / `--surface-2` / `--surface-3` | 画面の背景 / カード・面 / 入れ子の面 / 溝・ホバー |
| `--text` / `--text-2` / `--text-3` | 本文 / 補足 / 控えめな文字（白地で 4.5:1 以上） |
| `--brand` / `--brand-ink` / `--brand-soft` | 塗りのボタン / 文字・リンク / 薄い背景 |
| `--cue` / `--marker` | 手がかりの語句の強調 / 蛍光ペン風の下線 |
| `--ok` / `--warn` / `--error`（と `-soft`） | 完了・問題なし / 警告・未確認 / エラー |

意味のある色は `lib/colors.js` で決めています。

| 色 | 意味 | 見せ方 |
|---|---|---|
| 注目箇所の色（`FOCUS_COLORS`） | どの注目箇所か（番号ごと） | 番号の丸、問題文の印、気づきの左の線、吹き出しの枠、線 |
| 気づきの種類の色（`KIND_COLORS`） | 読み取り・型の判定・解法の選択・注意 | 薄い背景の札（塗りつぶさない） |
| 難易度の色（`DIFFICULTY_COLORS`） | 基本・応用・入試対策・実践 | 一覧の札 |

注目箇所の色と種類の色は似た色相を含むため、**注目箇所は塗り・線、種類は薄い札**と見せ方を分け、取り違えないようにしています。

## 3. 文字

- フォントは Noto Sans JP（400・700）。問題カードと吹き出しも同じフォントで描き、端末による見た目のずれを防ぐ。
- 見出し・ボタン・札は `font-feature-settings: "palt"` で仮名を詰める。本文は詰めない（読みやすさを優先）。
- 主な大きさ：本文 15px、問題文 18〜23px（画面幅で変わる）、気づき 16px、補足 12〜13px。
- 入力欄は 16px（iPhone で入力時に画面が拡大されないように）。

## 4. 形と余白

- 角丸：面 16px、ボタン・入力欄 10〜12px、札 6px（丸い札は 999px）。
- 影は3段階（`--shadow-sm` / `--shadow` / `--shadow-lg`）。普段は sm、持ち上げたいとき（ホバー・浮かぶ部品）だけ強くする。
- 押せるものは 44px 以上（小さいボタンでも 36px 以上）。
- 内容の幅は画面ごとに `--page-max` で決め、ヘッダー・本文・下の操作の幅をそろえる（一覧 1080px、作成ツール 860px、ほか 720px）。

## 5. 画面ごとの方針

### 一覧

- 冒頭に「どこを見て、何を考えるか」を蛍光ペン風に強調した一文と、完了した問題の割合。
- 科目ごとにまとめ、科目の札で絞り込む（件数つき）。並びは科目・単元・難易度の順。
- 問題カードは**どこを押しても「画面で見る」**で開く。カメラ（AR）とカードは小さなボタンで添える。問題文の冒頭2行を見せて選びやすくする。

### 学習画面

- ヘッダーの下端の細い線で、見た気づきの割合を示す。
- 表示の切り替え（立体・文字・カメラ）は区切りボタン（セグメント）。
- 番号ボタンは状態で見た目を変える：未読 = 枠だけ、途中 = 薄い塗り、いま見ている = 塗り＋外側の輪、見終わった = 右上に緑のチェック、次に見る = ゆっくり脈打つ輪。
- 問題文の印は**破線 = まだ見ていない、実線 = 見た、塗り = いま見ている**。立体表示（カード画像）と文字表示で同じ決まりにする。
- 「次へ」のボタンは常に1つ。スマホでは一覧の下端に固定し、気づきが増えても同じ位置で押せるようにする。気づきが増えたら新しい気づきが見える位置まで一覧を動かす。
- 立体表示の吹き出しは暗い面にし、画面の背景でもカメラの映像の上でも読めるようにする。中の並びは一覧の気づきと同じ（左の線 = 注目箇所の色、札 = 種類の色）。
- カメラ表示（スマホ縦）では、一覧を映像の上に半透明の暗い面で重ねる（トークンを暗い値に差し替える）。

### 振り返り

- 完了を伝える見出し、問題文全体に印をつけた図、気づきの種類の割合（帯グラフ）、注目箇所ごとの気づき（番号を縦線でつないだ時系列）。
- 下に固定した操作は「もう一度」と「次の問題へ」（一覧で後ろにある、まだ完了していない問題）。

### 作成ツール

- 手順を番号つきの面（1 基本情報 → 2 注目箇所と気づき → 3 管理情報 → 4 チェック結果 → 5 確認と書き出し）に分ける。
- ヘッダーにチェック結果（問題なし・警告・エラー）の札を常に出し、押すとチェック結果へ移動する。

## 6. 動きとアクセシビリティ

- 動きは「出てきた気づき」「次に見る番号」「完了の印」など、意味のある所だけに使う。OS の「視差効果を減らす」設定では動きを止める。
- キーボードで操作したときは、押せるものに太めの輪郭（`--focus-ring`）を出す。
- アイコンだけのボタンには `aria-label` を付け、アイコン（`components/Icon.jsx`）は読み上げから外す。
- PC（マウス）のときだけキー操作の案内を出す（`pointer: fine`。立体表示の「クリック／タップ」の呼び分けと同じ基準）。

## 7. アイコン

- 線のアイコンを `components/Icon.jsx` にまとめ、文字色に合わせて表示する。新しいアイコンも同じ太さ（2px）・丸い線端で描き足す。
- アプリの目印（ロゴ）は「問題文の1行に蛍光ペンで印をつけた形」。`public/thinking-icon.svg`（ファビコン）と `Icon.jsx` の `Logo` は同じ図柄にする。
